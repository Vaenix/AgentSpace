# 长视频问答中重复声画事件的定位与配对

版本 1.0 · 2026-11-19 · 首轮公开数据试探，技术样本另计。正文规定实验设计；实际完成情况见同目录《执行记录》。工作流按准备、标注、预测、评分、扩样顺序推进，候选题和工程试跑单独记录。

## 1　研究问题与反证

在同一个自然长视频中，某类声音出现至少两次，两次之后分别发生不同的可见动作。只改变提问中的序号，系统能否定位指定的声音，并判断紧接着开始的动作？“之后”指声音结束后最早开始的、可辨别的目标人物动作；持续中的动作、同时开始且无法判先后的动作应排除。一次连续的流水或一串连续脚步是否构成一个事件，要先统一该类别的切分规则。

- H1（待验证）　一些单题答错是把**同视频另一次**的真实动作作为答案。单题正确率可能掩盖配对失败。若错误并不比其他匹配干扰动作更集中于另一次，或盲猜已接近完整输入，需要重新解释。
- H2（待验证）　当检索已返回两个事件和足以识别后续动作的画面时，将每次发声与附近画面显式组织在一起可能有助于作答。若用相同内容和时序的普通呈现同样有效，应放弃方法增益主张；达到更高准确率或论文录用均无预设值。
- 推断范围　主回答器固定 Qwen2.5-VL-7B-Instruct。它接收帧与文字。音频检索或声音转成描述的模型、版本、输入、成本单独列出。手工真值转写、真实波形识别以及自动声音描述属于不同条件。

## 2　准备与选样（第 1–3 天）

| 执行项 | 产出及验收条件 |
|---|---|
| 登记数据 | 来源、版本或下载文件 SHA-256、许可入口、原始视频 ID、时长、可取回性及音轨。正式试探仅收录 ≥10 分钟的公开源视频。短视频可做读写和推理试跑，单列。 |
| 建立候选池 | 先找声学锚点，再找动作。EPIC-SOUNDS 与 EPIC-KITCHENS-100 按 video_id、时间对齐；TraceAV-Bench 按原证据链中的声音、时段与公开视频映射初筛。分别报告各源筛选流程与保留数。不同词可能描述同一次声响，相同声音类别也不保证指同一物理来源。 |
| 初始规模 | 10 个独立长视频 × 同题干两种序号 = 10 对、20 题。每个视频最多一对；候选不足就记录缺口。同一条视频的两个裁片不能充当两个独立视频。 |
| 固定样本 | 在查看模型输出前锁定题单、剔除理由、提问、选项、两个声音区间及动作区间。试跑时见过的候选标记为开发集，正式扩样按视频和原始录制会话隔离，EPIC 能按参与者隔离时再按人分组。 |

两套来源各有偏差。EPIC 的动作描述由视频标注提供，声音标注独立完成；时间相邻只能产生候选。初筛只覆盖厨房中的部分可辨声类。TraceAV 的分钟级轨迹可提示要查的区域，计算定位分数前需要秒级区间。数据与动作提示均放在评估侧。[EPIC-SOUNDS](https://github.com/epic-kitchens/epic-sounds-annotations) · [EPIC-KITCHENS-100](https://github.com/epic-kitchens/epic-kitchens-100-annotations) · [TraceAV-Bench](https://github.com/Heinz217/TraceAV-Bench)

## 3　复核题目与冻结金标（第 2–5 天）

1. 先导可由一人先完成可用性筛选并标为单人暂定，技术预测可同步推进。形成正式参考答案时，两位复核者分开看片并听音，不看动作标签、彼此答案或模型输出。先从视频开头核对前两次发声，防止采集片段之前有同类事件；标记声音起止、随后动作起止、主体和动作描述。短窗用于快速回看，原片用于判序。只有一人可用时保留为单人暂定。
2. 单独试只看静音画面、只听声音和只读题面，记录能否确定两次动作。静音已足以判序的样本可留作视觉对照；无法证明依赖声音的样本不计入声画必需主分析。遇到遮挡、多图合理答案、持续背景声难切分、来源不明确或音画不同步，记理由并复议或排除。
3. 将两人动作盲标对齐为稳定语义 ID（如动作对象＋动词）；保留原始措辞和分歧，不强行合并。记录两位对答案的一致数/总数、声音区间重叠、仲裁理由。两次答案必须不相同。主分析允许事先定义多个等价动作措辞映射到同一 ID。参考区间过短或边界高度含糊的题复议。
4. 每题使用同一组选项：第一次的动作、第二次的动作，以及两个同场景、但未在目标两次声音之后出现的可信动作。两问保持相同选项文本与排列；跨题对平衡正确选项位置，另行打乱位置做核查。一次会话只回答一道，顺序随机。盲检选项不透露先后（排除“再次”“继续”等答案捷径）。
5. 完整参考文件每题保留 pair_id、video_id、qid、序号、语义答案、声锚区间、动作区间、来源和复核状态。评分器使用 answer_id 及 interval_s（声锚区间）。模型文件只含题目、选项、公开输入和允许的候选片段，移除金标、证据链推理文本、带有答案的文件名。冻结包记录 SHA-256。正式预测后改题须换版本并重跑受影响的对照。

## 4　实验组与运行顺序（第 5–10 天）

先验证最简单的“两个事件已经取回”条件，再做从整段长视频检索的端到端实验。前者回答证据使用问题，后者才衡量检索。两种得分分别报告。

| 组别 | 可见输入和变化 | 能回答什么 |
|---|---|---|
| Q：只读问题 | 同题干与选项，不给媒体 | 是否可借措辞、选项排列或常识猜中？ |
| V：纯视觉检索 | 同一公开长视频和均匀切窗；用同一固定视觉检索器查询画面，仅给 top-k 片段的帧 | 画面本身已经足以做对多少？ |
| R：固定多通道检索 | 在同一时间网格上对视觉、声学检索分别排名，合并后取相同 k，再按时间排列；共用固定声音描述与选帧规则 | 普通多通道融合已有多大收益？保留 Muse 的题型路由作后续附加对照。 |
| P：显式声画配对 | 复用 R 的相同片段 ID、帧、文字、时间戳与排序，只改变声音描述与局部画面的分组 | 主方法比较 P−R。每组都显示相同时间信息，以免标签本身泄漏序号。 |
| O：人工给定候选 | 提供两个经复核的事件窗口，同时保留前后动作，**两问都给两段**。分别运行普通排序和显式配对；去掉所有“这段是本题目标”的提示 | 在两个相关事件已找回的条件下，模型能否区分？这是受控诊断。 |
| S：同视频错配 | 复用 P 或 O 的素材与预算，只交换两次声音的描述，画面与时间顺序不变。仅在两条描述确实含可区分信息时纳入，报告有效分母 | 模型是否对声画对应关系敏感？错误输入下的分数不能解释为正常使用收益。 |

实施起点：例如把原视频分成 8 秒窗、4 秒步长，保留 top-4，每窗等量采帧且包含临近后续动作。两次声音跨窗、动作在窗外分别编码为覆盖失败。跨源参数先仅在开发视频上调整。R 的可实现基线为固定视觉检索器＋文本到声音的 CLAP 检索器，按等权倒数排名合并，高重叠相邻窗去重。检索查询在诊断中先共用同一声类/问题语义（去掉“第几次”），让两题共享候选集合；按序选择留给回答器。推理期不得从人工声锚和动作表生成端到端输入。对 HiMu 等已有方法的实际复现或机制适配分别标记并记录模型、素材和预处理；论文公开结果不作同批差值。[HiMu 实现](https://github.com/DanBenAmi/HiMu)

受控表示试验使用与人工声锚独立的候选编号，预测选项和声锚区间。固定 Qwen 的模型修订、量化、视频缩放、帧预算、提示、温度（首选贪心）、最大输出长度和缓存策略。固定候选二选一的窗口选中率可作为辅助指标；若候选区间由人工直接给出，此时定位得分仅表示选中了哪个候选。若画面恰好只给两段且按顺序呈现，“第一次／第二次”可直接映射到位置，定位项只做格式检查；此类技术样本禁止出定位结论。正式的受控定位需在同一原片加入无目标声音的干扰窗，并用与序号无关的片段代号、平衡干扰窗位置。端到端 IoU 需要输出或估计发声本身的秒级起止，不能用含有前后动作的长裁片作为发声边界。若只能输出宽窗，改报该窗是否覆盖正确锚点，并将此结果与严格 IoU 分开。每组记录提示词数、图像数、冷启动/每题耗时、检索时间、描述生成时间与失败原因。

## 5　评分与诊断（第 8–12 天）

给 R 与 P 的自动声音描述仅由同一时间窗的音轨生成，禁止将视觉动作标注、问答选项或“第几次”写入描述。若两个窗都只能描述为同一种声音，应保留该样本并标记“描述相同”；这类样本上调换两条文字没有改变输入，S 条件没有可解释的效应。Q 条件只比较答案和选项偏好，定位记为不适用。

时间交并比 IoU = 两个时间区间的交集长度 / 并集长度。预设 IoU ≥ 0.5 认定位置命中；保留原始区间，以检查短促声的边界敏感性。预测同时等量覆盖两次声响时标为位置不明确。拒答、缺答留在分母中，另报覆盖率和运行完成数。

| 指标 | 固定分母和用途 |
|---|---|
| 单题答案正确率、声锚定位正确率 | 分别以全部已冻结问题为分母 |
| 成对联合成功率（主指标） | 两道题答案与定位全部正确的题对数 / 全部冻结题对数 |
| 错取另一次动作或位置 | 分别记录预测动作等于配对题答案、位置命中配对题区间，分母为全部冻结问题；同时列出其他错答、拒答和缺答，避免把一切错误归到错配 |
| 完全对调 | 两道题互选了对方的动作；再区分是否连定位也一起对调。按题对计数 |
| 检索链路 | top-k 是否覆盖两个声锚及两个动作；覆盖不足与全部覆盖但答错分开。若已覆盖且写出的声音描述遗漏关键事实，单列描述错误；证据不足时保留未定原因 |

优先读逐题差异表：P 比 R 有几对从失败转成功、几对反向；给定人工候选能否恢复；对调干扰是否改变预测。10 对中 1 对对应 10 个百分点，输出原始计数。先导不做发表级显著性判断。确认性扩样使用独立视频，根据先导中两种方法结果不一致的比例、希望检测的最小差异预估样本量；使用按视频聚类的区间估计和配对检验，预先指定单一主要比较 P−R。跨模型与其他消融作为次要分析。

H1 的四选项诊断分别统计选中“另一次的动作”、场景干扰动作甲和乙的次数；将前者与后两者的平均次数比较，同时公开每个干扰项的计数。两个干扰动作的可信度明显不相当时，先报告该限制。人工判定的声画必需子集须在看模型结果前登记，全体入选题也要报告；模型答对或答错不能作为剔除该题的理由。同一视频跑过调试（例如 P22_03）后，只计入先导开发分析，正式留出测试用新视频补齐。

## 6　1–2 周决策点

- **数据可行**：有 10 个不同长视频可由独立人员复核，两个声音、两个动作和序号均可辨。若不足，公布筛选流失原因，修正题源或缩小可声称的适用范围。
- **诊断可行**：同视频另一次错答在多个独立视频出现，可与“没找到声音”“动作不可见”“描述遗漏”区别。若只读题或纯视觉控制即可解决多数题，先剔除捷径或把主张收窄到视觉顺序。
- **保留方法**：同素材比较中，显式配对出现可复核的净改善，且并非来自额外帧、额外描述或泄漏。若普通排序表现相当，保留诊断、舍弃方法增益主张。
- **扩样**：先冻结新视频、原始样本和运行参数，再加第二模型家族和新声音场景。论文写作从研究问题、协议、局限性开始；实测数字、导师反馈和投稿状态须有独立记录。

如需联系最初的轻量 VideoRAG 方案，可在扩样后附加题型分流对照，并在 Video-MME 的原题上单列普通问答准确率。DrVideo、ReWind 的论文结果只作各自协议下的文献参考。只有用同一批新题、同样的可见数据和预算重新运行的方法，才进入主表作配对比较。智能眼镜旧数据、GPS 和 IMU 不参与本实验。

本机优先完成标注整理、媒体裁剪与量化推理。涉及租用 GPU、付费 API 或对外提交评测时单独确认费用与范围。截止日按研究启动后的天数安排，不构成对样本质量、提升或发表时间的承诺。
