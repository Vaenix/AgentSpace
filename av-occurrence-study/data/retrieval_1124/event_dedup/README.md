## 固定的去重规则

1. **事件**取 [audio_leads.csv](../../audio_leads.csv) 中 video530 持久化的三段合并区间。它们来自 applause／clapping 置信度不低于 0.5 的 3 秒 SoundAnalysis 窗；后一窗起点不晚于当前区间终点即合并。脚本先按同一规则重新合并 [audio_votes.csv](../visual/audio_votes.csv) 的 25 条记录，结果必须与这三段完全一致。
2. **命中**指窗与事件的正重叠秒数大于 0，首尾相接不算。
3. **候选顺序**沿用原排名：纯视觉按 `clip_mean_cosine`，联合按 `fusion_score` 降序；平分时起点早者在前，再按窗号。脚本先由已存分数重算竞赛名次和融合分，必须与 [grid_scores.csv](../visual/grid_scores.csv) 一致；再按原规则重选，必须与 [top4.json](../visual/top4.json) 一致。
4. **逐个扫描。** 两种变体都跳过与已选窗有正时间重叠的候选，这是原规则。去重变体另外跳过与已命中事件重叠的候选，即使该窗同时碰到新事件。没有检测重叠的窗不受事件规则影响。选满四窗即停。扫完全部候选仍不足四窗时，空位记为 `shortfall`，不放宽规则补位。

## 文件

- [summary.csv](summary.csv)：每个方法×变体的原片秒数、唯一检测事件数、每事件重复次数、多出的重复窗数、无检测重叠的窗数和候选不足数。
- [selections.csv](selections.csv)：四个名额逐行列出窗号、原片起止秒、分数、原名次、命中事件及重叠秒数；不足时该名额为 `shortfall`。
- [event_coverage.csv](event_coverage.csv)：每段事件被哪些入选窗命中。
- [decisions.csv](decisions.csv)：选满之前看过的每个候选及其入选或跳过原因、冲突对象。
- [edge_cases.csv](edge_cases.csv)：5 个合成样例及预期与实际结果，不是研究数据。
- [check.json](check.json)：一致性检查结果及输入、输出的 SHA-256。

相邻两窗命中同一事件和无检测窗都出现在真实数据中。全片 183 个网格窗都可作两组的候选，因此 video530 不会出现候选不足。不足四窗、平分、一窗同时碰到新旧事件这三种情况由合成样例覆盖；任何样例不符合预期时脚本以非零状态退出。

## 解读边界

- **单片开发数据。** 只有 video530 一部视频、一个声类和三段检测。该片此前已用于工程开发，结果只说明这一份快照中重复覆盖是否发生，不能外推到其他视频，也不宜在同一片上调规则后再评价。
- **机器检测只是代理参照。** 事件边界取决于分类器、0.5 阈值和合并规则。漏检的掌声不会成为事件，覆盖它的窗会被记为“无检测重叠”；两阵相近的掌声若被合并，会被当作同一事件去重；误检也会被当作事件。重叠 1 秒即算命中，不代表窗内包含完整声音或随后的动作。
- **联合组的命中数部分由构造决定。** 联合排名中的声音名次本身来自同一批检测，因此联合组命中检测事件更多，不能作为联合检索更好的证据。
- **不报告人工召回率。** 人工首次／第二次掌声及其后动作尚未独立核对，Recall@4 和问答指标均为未跑。
