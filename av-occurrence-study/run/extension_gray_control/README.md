## 解读限制

均匀灰帧是人为输入。回复仍然完整，可能反映文本或作答先验；回复改变，也可能只是模型对陌生视觉输入的反应。两种情形都不能说明正确率、是否用到音频信息，也不能说明模型内部依赖画面的哪些区域。本对照只有一个灰度值和一种图像尺寸，没有其他遮蔽方式。

## 复算入口

在 AgentSpace 仓库根目录运行，只需 Git、Python 3.11 或更高版本和已归档的文本，不需媒体、GPU 或模型。脚本先按 SHA-256 核对协议三文件、扩展批冻结输入和 #11 原文与账本，用标准库逐像素核对 `gray.png`。之后从 `87ee601` 读取解析器源码并核对 `4ebbd521…`，对两侧原文重放解析。逐行核对灰帧账本的旧严格解码字段和输入长度记录；无回复的可运行键必须在 `attempts.jsonl` 中有失败或中断记录。

```sh
python3 av-occurrence-study/run/extension_gray_control/summarize_gray.py \
  --output /tmp/gray-control-replay.json
cmp av-occurrence-study/run/extension_gray_control/statistics.json /tmp/gray-control-replay.json
python3 -m unittest discover -s av-occurrence-study/run/extension_gray_control -p 'test_*.py'
```

本机用 Python 3.11.7 和 3.12.0 各复算一次，输出与存档逐字节相同。离线测试覆盖：灰图尺寸与像素核对；计划键与冻结顺序一致；存档统计逐字节重放；各表求和；全弃答与失败键的分母（失败计技术缺失，不计弃答）；输入长度不符记为偏离；重复或篡改的账本行；运行器复用已有回复且不加载模型。

## 本机生成入口

不需要原帧或媒体。脚本在加载模型前完成全部核对；`replies.jsonl` 中已有原文的键直接复用，不重新生成，所以每键只保留首次原文。失败的键写入 `attempts.jsonl` 并保留原因，下次以同一输入重试。

```sh
/path/to/mlx-env/bin/python av-occurrence-study/run/extension_gray_control/run_gray.py \
  --model /path/to/checkpoint-fdcc572
```

对本目录存档重跑会复用全部 22 条回复，不加载模型。测试在账本副本上验证了这一点。
