# 扩展批的本机媒体准备

2026-11-24。以[冻结队列](../README.md)（`queue.jsonl` SHA-256 `363bc1da…`，合并指纹 `faabf53d…`）为输入，为 12 个题对的 24 个窗准备本地裁片与帧。入口是 [`../prepare_media.py`](../prepare_media.py)。本步不运行模型，不产生问答预测。

## 做法

- 运行前核对队列三份文件的 SHA-256 与合并指纹，并核对入选顺序。不符即中止。12 个名额全部保留，不做换样。
- 裁窗直接调用未改动的 `epic/recover_review_media.py`：用官方 MP4 的字节区间下载所需包，按 `epic/clip_bounds.py` 的秒数裁窗，转为 5 fps、480 宽的 H.264 和 24 kHz 单声道 AAC。该程序要求视频轨和音频轨都存在，两轨时长与计划相差不超过 0.6 秒，且整段严格解码无误。
- 入口另行实测每个裁片：ffprobe 时长与帧数，以 `-xerror` 解码两轨，记录音量（`volumedetect`）、字节数和 SHA-256。
- 取帧直接调用未改动的 `run/prepare_epic_smoke.py`，它再调用 `run/extract_frame.py`。规则不变：每窗取声音中点和动作 25%、75% 处三帧；任一点不在 `[窗起点, 窗起点 + 视频轨时长)` 内时，改为在窗内 20%、50%、80% 处等距取 3 帧。入口按同一条件给出替代原因，并与该程序的提示逐窗比对，不一致即中止。
- 实际取帧坐标：用 `-copyts` 和 `showinfo` 重复 `extract_frame.py` 的同一命令，确认重取的 PNG 与原输出逐字节相同，再记录该帧的显示时间。表中给出裁片内秒数，清单另有原片秒数。裁片为 5 fps，实际帧为请求时刻及之后的第一帧，最多晚 0.2 秒。

原片区间缓存、裁片和帧只写入 `--work-dir`。本目录只提交两份文本清单：

- `windows.jsonl`：24 行，每窗一行。字段包括计划窗、截去的动作秒数、状态、各轨实测时长与帧数、音量、SHA-256、取帧状态、是否替代及原因、每帧的请求和实际坐标与 SHA-256。若失败，另记失败原因。
- `summary.json`：计数、队列指纹、被复用程序与本入口的 SHA-256、FFmpeg 与 Python 版本。

## 复现

在仓库根目录运行。需要 `python3.12`、`ffmpeg` / `ffprobe`（本次 8.1.2）和 `/usr/bin/curl`。工作目录可以重复使用：已有裁片不会重新下载，已有帧会重新提取并逐字节比对，不一致即中止。`--output` 须为新目录。

```sh
python3.12 av-occurrence-study/run/participant_extension/prepare_media.py \
  --work-dir /tmp/av-participant-media \
  --output /tmp/av-participant-media/manifest \
  --check av-occurrence-study/run/participant_extension/media_prep
```

只验证首个视频时加 `--pairs P11_104-7`，其余窗记为 `not_attempted`。此时清单与本目录不同，不要加 `--check`。

工作目录中已有裁片但无法探测（例如空文件或截断文件）时，入口不会重新下载。该窗记为 `decode_failed`，写明 ffprobe 的原因、字节数和 SHA-256，同对另一窗与其余名额照常记录。要重取该窗，先把坏文件移出 `review_media/`。离线回归测试用一个空裁片加一个合成的有效裁片覆盖这种情况，需要 FFmpeg，不需要联网：

```sh
python3.12 -m unittest discover -s av-occurrence-study/run/participant_extension -p 'test_*.py' -v
```

已完成的核对：

- 全部 12 对按队列顺序运行一次，24 窗全部完成。
- 用同一工作目录再运行一次并加 `--check`，两份清单逐字节一致。重新提取的 71 帧也与第一次相同。
- 在全新工作目录中，从官方地址重新下载 P11_104-7。两个裁片的 SHA-256 和 5 帧的 SHA-256 与全量运行相同，这两行清单也逐项一致。
- 复现评审所述情形：在新工作目录放入有效的 `P11_104-7_2.mp4` 和空的 `P11_104-7_1.mp4`，运行 `--pairs P11_104-7`。修复前 ffprobe 抛出异常，整个任务退出且不写清单。修复后第 1 窗记为 `decode_failed`，第 2 窗记为 `decoded`，两份清单正常写出。修复后再次全量运行，`windows.jsonl` 与修复前逐字节一致；`summary.json` 只有本入口自身的 SHA-256 不同。

裁片和帧经 x264 编码，SHA-256 依赖 FFmpeg 版本和机器。换环境后 `--check` 可能只在哈希字段上不同，这时应比较状态、时长和坐标。
